# 自建素材大图上传失败修复

2026-11-06排查线上一店铺的三件自建素材。失败均处于图片准备阶段，尚未执行商品发布请求。

## 排查证据

- 图片文件在后台及调度器的共享静态目录中都存在，12张PNG均可完整解码。
- 单张原图约1.46～2.79MB；部分图片上传已收到HTTP 200及success=true，随后图片处理在约90秒后失败。
- 当前上传请求的总超时为90秒，批量异常原来统一显示“商品图片处理失败”，掩盖了超时类别。
- 原作者已核对版本与线上8e957a6的`common/services/xianyu_publish_media.py`具有相同Git对象ID；公开main源文件也采用直接上传原图和90秒超时。不是近期初始化、昵称或任务历史改动改变了这段图片上传逻辑。

## 本次修改

上传前在内存中生成优化副本：超过1MiB或最长边超过1920像素的静态图片按比例缩放。普通图片保存为JPEG，透明图片继续使用PNG并保留alpha。小图不重新编码，动画不展平。RGB颜色配置保留；CMYK带配置时先转换到sRGB，避免将CMYK配置附给RGB输出。上传MIME、扩展名和发布尺寸对应实际发送的字节。

素材原文件、素材记录、发布类目和商品内容不修改。图片上传超时给出固定中文提示；批量发布仍依据实际提交阶段区分明确失败和结果待核查，不自动重发商品。

## 验证与范围

- 10项专项测试：初始9项先复现6项失败，再全部通过；独立审查发现ICC丢失，新增颜色配置回归先失败再通过。覆盖大PNG、小图、尺寸、透明通道、颜色配置、EXIF方向、动画、损坏图片、超时及批量安全提示。
- 269项首轮服务回归通过；颜色配置修复后最终270项通过（后台261、WebSocket 6、调度器3）。
- 真实12张图片仅在服务端独立Python进程中读取并在内存中运行候选处理函数，优化结果229643～358610字节，输出可解码且静态图最长边不超过1920。每份原文件的SHA-256前后相同。
- 该验证没有调用图片上传或商品发布接口，没有安装或替换线上代码。真实平台发布仍须上线后由用户重试验收。

本修复基于线上稳定8e957a6，独立于尚未完成的拼多多模块。
