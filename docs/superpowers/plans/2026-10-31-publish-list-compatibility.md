# 发布列表兼容优化实施计划

> **For agentic workers:** 使用 superpowers:executing-plans，在当前会话逐项实施与验证。

**Goal:** 在保持现有业务行为的前提下，让素材库和发布日志复用分页组件，阻止过期请求覆盖当前列表，并提供可重复运行的回归入口。

**Architecture:** 沿用现有 Pager 和 API，只增加一个请求生命周期 hook。保留素材库当前页选择规则、批量发布跨页选择规则、店铺权限及全部写操作流程。

**Tech Stack:** 现有 React、TypeScript、Node test runner、Playwright CLI、Python unittest 和本地 Docker 服务，无新增产品依赖。

**Spec:** 用户已同意上轮提出的第一批优化，并要求“确保现在的功能不被损坏”。本计划将范围收敛到发布相关的两个列表及其回归验证。

## Global Constraints

- 基线提交 bd9b230；保留本地基线分支及前端构建备份。
- 不修改后端业务代码、数据库、退款、打单或商品发布接口。
- 不改变素材原文、店铺范围、勾选规则和发布任务的状态语义。
- 浏览器测试只使用合成数据并拦截所有 API；未声明的写请求一律阻止。
- 本轮先完成本地验证，不推送远端或触发生产部署。

## Approaches

- 采用：现有 Pager 加小型请求生命周期保护，修改范围有限，可覆盖现有交互。
- 未采用：整站列表重写或引入新数据请求框架，涉及过多页面，增加兼容验证范围。

## Review Focus

- 慢旧请求在新请求之后返回，不能覆盖新列表或提前结束加载状态。
- 清空后空列表和跨标签任务历史联动仍正常；加载过程中禁用日志分页。
- 筛选重置和非首页查询只请求正确的第一页，不能回写旧筛选。
- 删除最后一页后页码应返回有效页，空列表仍允许切换条数。
- 素材库当前页选择与批量发布跨页保留选择分别保持原规则。
