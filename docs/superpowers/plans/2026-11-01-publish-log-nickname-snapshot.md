# 发布日志历史昵称留存修复

用户反馈旧发布记录仍显示数字ID。已确认上次只根据当前账号列表渲染昵称，历史账号已移出本地列表时无法识别。通过已有SSH按完全相同的闲鱼账号ID查到服务器可信资料缓存，确认该历史账号昵称为芋圆奶茶；不根据当前店铺或相似名称猜测身份。

## 修复范围

- 发布日志增加可空account_nickname字段，创建日志时读取有权限的目标账号资料缓存保存昵称快照，不接受客户端自填昵称。
- 启动时幂等追加字段，只为同所属用户、同账号ID且快照缺失的日志补齐有效缓存昵称，不覆盖已保存昵称、发布结果、清空标记或时间。
- 删除账号前为该账号尚无快照的历史补齐昵称，再沿用原有账号删除；不改变发布任务和日志清理规则。
- API返回昵称快照；前端优先使用可信快照，当前账号昵称仅作缺失回退。账号ID保留悬停提示，不再与已知昵称并列显示数字。
- 本地历史17条使用已核实的同ID资料补齐昵称，仅更新展示元数据，保留原ID、状态、清空标记和时间，并保留最小回退记录。

- [x] 浏览器模拟账号列表缺少历史账号，仍显示真实快照昵称；同名ID放提示，测试不真实发布。

验证结果：53项Node测试、前端构建、258项Python测试及7组浏览器流程全部通过。新增真实路由回归覆盖昵称快照及清空过滤；本地已运行服务的HTTP查询结果与数据库可见记录数一致。17条旧记录仅补齐昵称，原ID、发布状态、清空时间和更新时间逐项相同。已清空的历史保持清空，不恢复展示。独立只读审查无阻断问题。

根因补充：页面实际日志接口仍使用backend-web中的旧查询实现，未沿用公共服务的清空过滤与昵称序列化；现已统一为公共查询服务，保留管理员用户名补充和商品链接格式。
