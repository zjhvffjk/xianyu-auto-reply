# 批量发布异常不阻断剩余商品

## 已确认问题

线上核查接口提交成功后，序列化数据库自动更新的 `updated_at` 触发隐式异步读取并抛出 MissingGreenlet；因此记录已经保存，网页却提示内部错误。现有执行器对单条 unknown 主动暂停整批，历史任务即使人工核查完也不能继续。

## 处理范围

- 核查提交后显式异步刷新日志，再返回完整数据；异常时只返回可操作的固定提示，保留用户和店铺校验。
- 单条响应未知保留 unknown，永远不自动重发；剩余 pending 商品按既定间隔继续，包含进程中断后租约恢复。
- 队列全部处理后，仍有 unknown 则标记 attention，全部核查后结束；取消始终优先，不恢复已取消任务。
- 历史 attention 任务不会在升级后突然发布，提供“继续剩余”供用户明确触发；仅领取 pending，不重发成功、失败、取消和 unknown 项。
- 核查旧的未知项可在其他商品执行时保存；同一项仍在执行时拒绝人工覆盖。
- 使用现有批次、日志、锁和调度器，不改发布接口、定价、素材、图片优化和其他平台模块。

## 验证边界

本地 MySQL 与模拟平台执行，先复现核查返回错误、unknown 阻断及历史恢复缺失，再验证顺序、取消、迟到响应、租户隔离。浏览器模拟接口验证恢复入口和错误提示，不真实发布商品或修改线上任务。
