# 快递打单使用说明

本地入口：[9001 订单管理](http://127.0.0.1:9001/orders) → 快递打单。

目标是由平台统一申请服务商应用，让各用户授权自己的店铺、拼多多电子面单，设置发件人并在本系统打印。2026-10-29已按官方免登和店铺回调协议实现本地授权入口、确认与撤销，平台配置、订单核对和访问隔离继续可用。真实应用授权、电子面单和打印仍待联调，不能宣称真实打单已接通。

## 普通用户

- 在“接入状态”查看平台进度，无需注册开发者或填写 AppKey、AppSecret。
- 可以按自己的店铺核对订单收件信息、查看历史打单记录和复制单号。
- 平台配置完成后，点击“准备店铺授权”，再点击“前往官方确认”；完成官方登录后刷新授权状态。只有服务器验签并匹配当前用户和店铺的回调，才会显示“店铺登录已确认”。授权链接不写入浏览器存储。
- 待确认请求15分钟过期；可撤销本地授权，旧请求随后无法重新确认。撤销只解除本系统绑定，不注销快递助手账号。
- 店铺登录确认不代表电子面单已授权。电子面单、发件人和打印机配置仍待正式联调，当前普通用户不能同步远端订单、申请单号或打开管理员测试工作台。
- 即使店铺曾保存旧版开发者连接，也不会将它当作用户授权。

## 管理员

- “平台接入”中统一保存服务商应用的 AppKey、AppSecret。凭据加密保存，密钥不回显、不写入浏览器存储；留空保留已有密钥，更换 AppKey 必须同时填写对应的新密钥。
- 保存应用只表示凭据已保存，不代表审核通过、用户已授权或已经验证可用。
- 平台配置中显示店铺回调路径`/api/v1/waybills/provider/callback`。正式联调需先部署到公网HTTPS域名；127.0.0.1不能接收服务商回调。本轮只处理`user.push`及`user.login`，尚不处理发货回传，不应直接覆盖已有业务的发货回调。
- “管理员接口测试 · 旧连接”保留原有逐店铺连接，用于核验已有打印接口，与平台应用分别保存。测试功能会发送真实请求，使用前确认权限和测试订单；本次开发测试全部模拟服务商。
- 管理员测试流程仍保留订单核对、逐笔同步、已有单号复用和未知结果暂停。取号不代表纸张已打印，也不会更改闲鱼发货状态。

## 后续联调

1. 用户2026-10-29截图已显示现有应用“上线中”并分配凭据。将现有凭据填写到本机平台接入页面，先核验连接和对应接口权限，无需重复申请应用。凭据不发聊天、不写入源码或文档。
2. 核对现有应用接入类型、回调配置和多商家权限，部署公网回调后，验证真实免登、回调签名格式和本地店铺归属。用户不能自行填远端商家 ID 充当授权。
3. 联调拼多多面单、邮政／极兔／圆通模板、各用户自己的发件信息和打印组件，确认系统内打印方式与费用，见[服务商接入申请准备](快递助手服务商接入申请准备.md)。
4. 经允许后使用一笔实际订单验证同步、取号和纸张打印；闲鱼物流发货单独核验。

关闭窗口只暂停后续订单。已经提交但结果不确定的请求应先核对服务商实际结果，不能盲目重试。

## 本轮验证

后台采用真实 MySQL 连接私有临时表与模拟服务商，40项检查通过，覆盖平台凭据加密、管理员权限、授权签名、过期/撤销/配置变化、归属、幂等及原取号保护；Node49项、生产构建与两种角色页面验收通过。使用Playwright模拟服务商验收，未真实授权、申请单号、打印或提交发货。完整结果见2026-10-29店铺授权实施计划。
