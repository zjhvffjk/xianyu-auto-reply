## 已确认的使用目标

我们维护自己的闲鱼订单系统，在系统内向多个用户提供快递打单。各用户分别授权自己的店铺、电子面单账号并设置发件人和打印机。开发者的个人地址、面单额度和店铺不能作为所有用户的公共配置。

首批面单需求为拼多多电子面单，快递优先邮政、极兔、圆通。用户在本系统选择订单和模板、发起打印，并查看单号及结果。面单授权可能需要进入服务商或电商平台的官方页面，但日常打单应在本系统完成。

## 官方资料已证实的能力

- [开放平台打印接入方案](https://open.kdzs.com/home/jjfa/)明确列出“平台入驻的商家”订单接入，支持同步商家订单、批量打印及回传单号；页面给出的流程是接入咨询、评估、确定合作、技术联调。
- [官方产品介绍](https://open.kdzs.com/?source=kdzs)提供“一站式打印发货集成页”，并说明电子面单支持自营型、入驻型、代发等场景，包含拼多多电子面单。
- 以上证明有适配本需求的产品方向，不能据此断言现有应用已获得多商户权限、集成页可在我们的域名嵌入，或特定商家的拼多多面单可用于闲鱼订单。授权协议、开放接口和服务商确认才是实施依据。

## 需要服务商一次确认的问题

1. 本需求应使用打印开放平台的入驻型方案，还是 ERP 自建商城方案？是否允许当前申请主体开通，需提交哪些主体材料？现有应用能否调整，无需重复申请？
2. 是否支持一个平台应用关联多个独立商家？商家身份如何创建、授权和撤销，订单、模板、面单余额与发件信息分别如何隔离？请提供正式授权协议及接口文档。
3. 集成打印页是否可在本系统内使用？请提供嵌入或 SDK 示例、域名配置要求、浏览器限制、打印组件要求，以及区分取号成功、打印受理和实际打印结果的方法。
4. 拼多多面单用于闲鱼订单是否允许？邮政、极兔、圆通分别需哪些店铺订购、面单授权和额度条件？
5. 是否每个商家必须单独开通或付费 ERP？平台应用、商家授权、API调用、面单、打印组件分别如何收费？请提供当前正式报价和试用条件。
6. 单号和发货结果通过哪种签名回调或查询接口获得？是否支持幂等、结果补查和撤销授权后的存量订单查询？

## 现有代码核对

已存在订单核对、按用户与闲鱼店铺限制访问、加密保存连接、同步订单、取号幂等保护和打单记录。当前客户端调用 `kdzs.print.*`，并支持传递 `mallUserId`，但这不构成远端商家授权或隔离已获验证的证据。

当前页面由管理员统一填写平台凭据，普通用户已有店铺免登授权入口，后台验签确认并支持本地撤销。原逐店铺开发密钥仅保留给管理员测试，普通用户仍不能真实同步取号。打印集成页、面单权限和真实商家回调尚待联调，不应把本地实现称为服务商模式已完成。

## 拟采用的技术方向

优先评估官方打印集成页，满足系统内操作且可独立隔离商家的前提下复用官方模板和打印组件；如果官方仅提供跳转工作台，则评估正式取号／打印 SDK，自建本系统内的打印操作。ERP 自建商城流程只有在官方确认适合多商户和系统内打印时才采用。

实施时将平台应用配置与商家绑定分开：应用密钥只由管理员在服务端管理，普通用户操作店铺授权、面单、发件人和打印机。绑定、撤销、回调和记录均按本系统用户与店铺核对归属，外部参数不能自行决定租户。

回调必须采用服务商确认的验签和结果查询协议；不接受凭前端提供的单号直接覆盖订单。取号、打印受理、打印结果和闲鱼发货分别记录，重复回调与超时不能引起重复取号。闲鱼实际物流发货接口仍需单独核实。

代码实施的前提是获得适用的授权／打印接口契约并确认设计；当前不凭教程或产品宣传臆造授权接口，不进行真实取号、用户授权、套餐购买或生产部署。
